## 2. 기능별 "AI로 만든 과정" 증거물
### QUEST 시스템 (진행 중)
- **확정 방향**: 메타 누적 도전과제(Career Challenges) — 영구 티어형. 매 판 종료(`CommitResult`) 시 평생 스탯(처치/되감기/골드/최고생존) 누적, 목표 티어 도달 시 **수동 수령 버튼**으로 골드 획득 → 상점 순환. 타이틀 로비에 퀘스트 패널.
- **핵심 설계 근거(designer, 코드확인)**: 정산 1지점(`CommitResult`)에서만 판정 → 실시간 훅 최소. 골드경제 그대로 얹힘. QuestData SO(`Resources/Quests/`)=ShopItemData 패턴 복제. 되감기 횟수가 자연스러운 퀘스트로 게임 정체성 계량화.
- **신규 코드 계약**: GameData에 Lifetime 3필드 + QuestProgress(수령 티어) 리스트(null-guard) / RunKills·RunRewinds 카운터(OnDead·DoRewind 1줄씩, GameScene.Awake 리셋) / QuestService(Evaluate at CommitResult + 수동 Claim) / 퀘스트 에셋 4종 / 타이틀 퀘스트 패널(ui-kit, UI_ShopItemCell 재사용).
- **일일퀘스트**: MVP 제외. QuestData에 resetPeriod 드롭인으로 후속 확장 가능(서류 확장성 어필).
- plan.md: `_workspace/plan.md` _(스냅샷 보관 필요 — 다음 작업 전 복사)_

### 보스 시스템 (완료, 2026-07-28~29) — **파이프라인 완주 사례 · 서류 메인 소재 후보**
- **규모**: 커밋 3개(`29ed438` Stage1~6 / `ac389f0` Stage7~9 / `5ce5362` 페이즈2 보강), 신규 C# 10파일 + 수정 20여 파일
- **파이프라인 한 바퀴**: game-designer(기획) → **사람이 방향 확정** → game-planner(`plan.md`) → game-coder ×6(Stage 단위) → game-ui-artist ×2(HUD·레이아웃) → 사람이 플레이 검증
  - 각 단계 호출 프롬프트가 그대로 "AI 지시사항" 증거물. **Stage 단위로 쪼갠 것이 AGENTS.md "복잡한 기능은 단계별로" 규칙의 실제 적용례**
  - plan.md에 단계마다 "**여기서 멈춰도 동작하는가**"를 명시 → Stage 6이 최소 출하선, 7~10은 컷 가능하게 설계
- **AI가 내린 설계 판단(근거 포함) — 서류에서 가장 보여줄 만한 부분**
  - **Rewind 스냅샷 배치 3안 비교 후 채택**: `EnemySnapshot` 확장(1개체용 필드를 적 300×100프레임에 부과) / 별도 링버퍼(인덱스·리셋 2벌 → 어긋나면 재현성이 조용히 깨짐) / **`FrameSnapshot`에 프레임당 1개**(기존 `WaveSnapshot` 선례) → 3안 채택
  - **일반 적 파이프라인 편입 여부를 항목별로 판단**: `EnemyBase`·SpatialHash는 편입(무기 판정·되감기 재사용), GPU 인스턴싱·Burst Job은 **의도적 제외**(개체별 색 제어 불가 / 잡몹에 밀리면 패턴 시작 위치가 흔들려 결정성 붕괴)
  - **"EnemyBase 수정 금지" 제약을 근거를 들어 깬 사례**: 되감기 캡처가 `EnemyMover.AttackCooldown`만 읽어 보스 쿨다운이 유실 → virtual 프로퍼티 추가가 기존 확장 패턴(Init/OnDead/RestoreSnapshot)과 동일하고 hot path의 `as` 캐스트도 제거됨을 근거로 제시 → 채택
  - **데이터 주도 설계 자체 검증**: `BossData.patternSequence[]`로 "2번째 보스를 C# 0줄로" 를 목표화하고, 구현마다 `Length` 가정 금지를 리뷰 항목으로 유지
- **기획 판단 = 게임 정체성 연결(designer)**: 패턴 순서를 **고정 시퀀스**로 → 되감기가 "주사위 재굴림"이 아니라 **"재도전"**. 보스 HP도 함께 되감겨 **그 자체가 남용 방지 장치**(별도 페널티 시스템 불필요)
- **AI 판단을 사람이 뒤집은 사례 (서류에 솔직히 쓰면 오히려 강점)**
  - **Stage 10(2번째 보스) 취소** — AI는 "코드 0줄이라 ROI 최고"로 권고했으나, 신규 패턴 0인 리스킨이라 "콘텐츠 깊이" 약점을 못 건드리고 데이터 주도 증명은 이미 4회(Weapon/Shop/Quest/Wave) 했다는 판단으로 사람이 취소 → 남은 기간을 밸런스·GIF·문서화로
  - **보스 등장 방식** — AI 초안은 런 중 등장만. 사람이 "심사위원이 3분 생존할 리 없다"를 지적 → BOSS RUSH 데모 진입 추가(새 씬 없이 플래그 + `JumpTo`)
  - **페이즈 2 체감 부재** — 사람이 "색만 바뀐다"고 지적 → 한 바퀴 22.6초 vs 전투 35~45초라 25% 단축이 표본에 안 잡힌다는 계산으로 원인 규명 → 속도·피해 축 추가
- **AI가 틀렸던 것(교훈으로 기록)**: 리쉬 거리 18을 **가로 화면 전제**로 산출(세로는 화면 반대각선 11.5) / 잡몹 프리팹에 SpriteRenderer·Rigidbody2D가 없다는 사실을 놓치고 "복제하라"고 안내 / 생성기 실행 순서를 바꾼 안내가 캔버스 오탐 중복을 유발
- **KB 신규 3건 — 실제로 밟은 버그에서 생성**(AI 워크플로 자산화의 실증)
  - `bug-patterns/instanced-enemy-prefab-lacks-components.md` — GPU 인스턴싱 프리팹엔 SpriteRenderer/RB2D가 없어 복제한 보스가 안 보이거나 중력에 낙하
