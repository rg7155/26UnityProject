# 치비 캐릭터 네온 규격 v2

`개발_진행상황.md` L109의 「4방향 대칭 네온 규격」을 대체하는 규격이다.
v1의 '4방향 대칭'은 근거가 된 전제(유닛이 회전한다)가 사실이 아니어서 폐기했다 — 3절 참고.
v1은 용어만 있고 정의가 없어 생성물마다 여백이 달라졌고, 그 결과가 PPU 5종·머티리얼 UV 3종이라는
수동 보정 부채로 남았다. v2는 **여백을 반입 단계에서 기계적으로 통일**해 그 부채를 없앤다.

## 1. 캔버스와 해상도

| 구분 | 생성 캔버스 | 반입 해상도 |
|---|---|---|
| 전투 유닛 (플레이어·적·무기·탄환) | 1024 × 1024 | **512 × 512** |
| 4프레임 스트립 | 4096 × 1024 (가로 1열) | **2048 × 512** (512 프레임 4개) |
| 보스 | 1024 × 1024 | **1024 × 1024** |
| 배경 타일 | 1024 × 1024 | 1024 × 1024 (기존 유지) |

임포트 PPU는 기본 512다. 단 플레이어는 기존 화면 크기
`1254px / 577PPU ≈ 2.17유닛`을 보존하기 위해 **236 PPU**를 쓴다
(`512 / 2.17 ≈ 236`). 프리팹 Transform Scale은 Collider에도 영향을 주므로 크기 보정에 쓰지 않는다.
Unity `maxTextureSize`는 정지 이미지 1024, 일반 4프레임 스트립 2048,
보스 4프레임 스트립 4096으로 자동 적용해 프레임당 반입 해상도를 보존한다.

게임 해상도는 **540 × 960 세로 고정**이다. 기존 에셋이 1254px였던 것은 명백한 과잉이고,
512로 내려도 화면상 실루엣은 동일하다. WebGL `data` 용량에도 유리하다.

**프레임 수는 4로 고정한다.** 늘릴수록 생성 모델의 프레임 간 일관성이 급격히 나빠진다.

## 2. 배경 — 그린스크린, 알파 아님

```
배경색 #00FF00 (균일한 밝은 녹색, 완전 불투명)
```

이미지 생성 모델은 알파 채널 PNG를 안정적으로 만들지 못한다. 그래서 단색 배경으로 뽑고
반입 단계에서 알파를 뽑는다 — 여기까지는 `_workspace_archive/plan_scrolling_bg.md`(배경 타일)와 같다.

**다만 전투 유닛은 검정이 아니라 녹색이다.** 배경 타일은 가산 합성이라 검정이 곧 투명이지만,
전투 유닛에는 **어두운 내부 채움**(dark core, 음영 패널, 코어를 두르는 검은 링)이 있어서
검정 배경으로 뽑으면 그 부분까지 투명해져 **구멍이 뚫린다.**

기존 9장도 실제로 그린스크린으로 만들어졌다 — `ArtSource/Generated/Source/`의 코너 픽셀이
`#20E820` 부근이다. 이 사실은 문서화된 적이 없었고, v2에서 규격으로 명문화한다.

**크로마키 → 알파 변환과 초록 번짐(spill) 제거는 `tools/art_import.py`가 담당한다.**
판정은 녹색 지배도 `d = G - max(R, B)` 기준이며, `d >= 90` 완전 배경 / `d <= 30` 완전 피사체 /
사이는 선형 램프로 안티에일리어싱 경계를 보존한다.

### 녹색 계열 대상 예외

팔레트에 녹색이 있는 대상은 배경과 함께 지워진다.
**`Positive #79E86A`, 연사탄 `RapidShot #C7FF00`은 흰색으로 생성한 뒤 프리팹 틴트로 색을 입힌다.**

## 3. 시점과 방향 — 측면(3/4) 뷰, 전부 오른쪽

**캐릭터는 오른쪽을 보는 3/4 측면으로 그린다. 왼쪽 버전은 만들지 않는다.**

v1은 「4방향 대칭」이었고 근거는 "탑다운에서 이동 방향으로 회전해도 방향성이 안 보이게"였다.
**그 전제가 사실이 아니었다.** 코드를 확인한 결과 회전하는 것이 하나도 없다 —
`EnemyMover.cs:40`은 `transform.position`만 갱신하고, 발사체도
`ProjectileWeapon.cs:50`에서 `Quaternion.identity`로 고정된다.

레퍼런스인 탕탕특공대(Survivor.io)의 실제 인게임을 확인한 결과 **측면 뷰**다 — 플레이어도
적 병사도 총을 옆으로 겨눈 채 좌우로만 뒤집힌다. (뱀서는 정면 뷰라 관례가 갈리지만,
이 프로젝트의 레퍼런스는 탕탕특공대다.)

**측면이 무기 문제도 같이 푼다.** 정면으로 총을 들면 총구가 화면을 향해 어정쩡한데,
측면이면 겨누고 쏘는 자세가 자연스럽게 나온다.

### 좌우 반전

`transform.localScale.x = -1`로 처리한다. 인스턴싱 적도 이 값이 `localToWorldMatrix`에 실려
나가므로 **셰이더 없이 동작한다.** 아트 장수가 절반이 된다.

⚠️ **음수 스케일은 삼각형 와인딩을 뒤집는다.** 적 머티리얼 3종이 현재 `_Cull: 2`(Back)라
그대로 두면 반전된 적이 컬링되어 사라진다. **`_Cull: 0`(Off)으로 바꿔야 한다** —
`Mat_Enemy_Basic_Sprite` / `Mat_Enemy_Speeder_Sprite` / `Mat_Enemy_Tanker_Sprite`.

### 반전 중심 — 무기 오프셋 자동 보정

무기가 한쪽으로 튀어나오면 바운딩박스가 그쪽으로 늘어나 **몸통이 반대편으로 밀린다.**
그 상태로 좌우 반전하면 몸이 좌우로 점프한다(실측: 플레이어 1차본에서 40px).

`art_import.py`가 **상단 30% 영역(머리)의 알파 무게중심**을 가로 정렬 기준으로 쓴다.
사람형은 머리가 몸통 바로 위에 있어 무기 무게에 끌리지 않는다.
`TARGETS`의 `humanoid=True`가 이 보정을 켠다. **수동 피벗 조정은 하지 않는다.**

### 방향성이 필요한 예외

- `Projectile` / `Projectile_Rapid` — 회전하지 않으므로 **회전 대칭인 구체 형태**로 만든다.
  방향성 있는 탄환을 쓰려면 `ProjectileWeapon.cs`에 진행 방향 회전을 한 줄 추가해야 한다
- `Orbiter` — `OrbitWeapon`이 위치만 갱신하므로 회전 대칭이 안전하다
- `TelegraphRing` / `TelegraphFill` / `BossRadialProjectile` — 회전 대칭 (원형)

## 3-1. 캐릭터 규격 — 치비

**2.5등신 치비.** 큰 머리, 짧고 뭉툭한 다리, 넓고 단단한 체형.

- **실루엣이 전부다.** 화면상 수십 px이라 얼굴 디테일은 보이지 않는다.
  머리 모양·장비 실루엣·전체 비율로 구분되게 만든다
- **얼굴은 최소로.** 바이저 한 줄 또는 눈 한두 점. 코·입·표정을 넣지 않는다 —
  프레임 간 일관성이 무너지는 첫 번째 지점이다
- **무기는 스프라이트에 그려 넣는다.** 무기 5종(`Projectile`/`RapidShot`/`AoE`/`Orbit`/
  `Lightning`)이 동시에 장착되므로 손에 든 무기를 장착 무기와 연동할 수 없다.
  탕탕특공대도 같은 이유로 무기는 고정 장식이다. **추가 에셋 0, 코드 변경 0**
- **어두운 배경에서 실루엣이 떠야 한다.** 게임 배경이 `#10131C`라 아머를 near-black으로
  칠하면 묻힌다. 베이스는 **미디엄 그레이** 이상으로 올린다 (플레이어 1차본의 실패 지점)
- **굵은 외곽선.** 어두운 배경 위에서 형태가 뭉개지지 않게 한다
- **적 3종은 실루엣으로 구분한다.** 색만 다르면 플레이 중 구분이 안 된다
  (표준 / 날렵한 스카우트 / 육중한 중장갑)

세계관은 유지한다 — 사이버 회로 배경(`CyberMetalPanelTile` / `CyberCircuitEdgeTile`)과
네온 팔레트는 그대로 두고 **캐릭터만 치비로 바꾼다.** 검증된 배경 타일 2장을 버리지 않는다.

## 3-2. 레퍼런스 이미지 — 일관성의 핵심 수단

**프롬프트 문구보다 레퍼런스 이미지가 효과가 크다.**

1. **플레이어를 먼저 확정한다.** 이 한 장이 스타일 기준점이다
2. 이후 **모든 생성에 채택된 플레이어 이미지를 레퍼런스로 첨부**하고
   "match the art style, line weight, proportions and shading of the reference image"를 덧붙인다
3. 4프레임 스트립을 만들 때도 해당 대상의 정지 채택본을 레퍼런스로 첨부한다

탄환·텔레그래프처럼 스타일을 따라가는 대상을 먼저 만들지 않는다. **스타일을 정하는 것부터 만든다.**

## 4. 여백

피사체가 프레임의 **82~88%**를 차지한다.

생성 단계의 여백은 엄격하지 않아도 된다 — `art_import.py`가 알파 바운딩박스로 재크롭한 뒤
정사각 캔버스에 균일 패딩으로 다시 앉힌다. **이 재크롭이 UV `scale 1 / offset 0`과
PPU 단일값을 보장하는 근거다.**

**스트립은 전 프레임 공통 바운딩박스와 공통 스케일을 쓴다.** 사람형은 프레임별 머리 중심만
가로 중앙에 정렬해 생성 모델의 수평 드리프트를 제거한다. Y축 차이는 바운스를 살리기 위해 유지한다.
프레임 실루엣 크기 편차가 3%를 넘으면 경고하고 자동 스케일 보정하지 않는다.
단, 이동 사이클의 가로 편차가 팔·다리 보폭에서 생기면 의도된 동작으로 볼 수 있다.
이때는 세로 크기·머리 중심·헬멧·몸통·장비의 일관성을 따로 판정한다.

## 5. 팔레트

`Assets/Scripts/UI/UITheme.cs`의 실제 값과 일치시킨다.

| 이름 | Hex | 용도 |
|---|---|---|
| AppBg | `#10131C` | 게임 배경 (생성 시 배경은 `#00FF00` 그린스크린) |
| Cyan | `#35D9F5` | 플레이어, 아군 계열 |
| Danger | `#FF5488` | 적, 보스 |
| HitFlash | `#FF1E1E` | 피격·위험 경고 |
| Gold / Accent | `#FFC23C` | 강조, 보상, 기본 탄환 |
| Positive | `#79E86A` | 긍정 피드백 |
| RapidShot | `#C7FF00` | 연사 탄환 (`Projectile_Rapid.prefab` 현재 틴트값) |

**대상은 목표 색으로 직접 생성한다.** 흰색으로 뽑아 프리팹 틴트로 물들이지 않는다 —
네온 디테일이 틴트에 뭉개진다. 반입 후 프리팹의 `m_Color`는 흰색(`1,1,1,1`)으로 되돌린다.

**예외는 녹색 계열뿐이다**(2절 참고). 연사탄만 흰색 생성 + 틴트 유지로 간다.

## 6. 조명

**flat lighting.** vignette 금지, glow hotspot 금지, 그림자 금지, 원근 금지.

발광은 게임의 Bloom이 담당한다 — `Assets/Scenes/GameScene/@PostFX Profile.asset`,
`intensity 1 / threshold 0.6 / scatter 0.7`. **이미지에 미리 구운 발광은 Bloom과 이중으로 먹어
형태를 뭉갠다.** 밝은 선은 선명하게, 번짐은 엔진에 맡긴다.

## 7. 금지 요소

텍스트, 로고, 서명, 워터마크, 드롭섀도, 원근, 배경 소품, 프레임/테두리.

## 8. 채택 기준

**정지 이미지** — 512로 축소해 게임 화면(540 × 960)에 올렸을 때 **실루엣이 식별되면 통과.**
픽셀 단위 디테일은 판정 대상이 아니다. 적은 화면상 수십 px에 불과하다.

**애니메이션 스트립** — 4프레임을 순환시켰을 때
① 피사체가 **자리에서 이탈하지 않고** ② **실루엣 크기가 튀지 않으면** 통과.
프레임 간 디테일 차이는 문제가 아니다. 위치와 크기가 흔들리는 것만이 문제다.

## 9. 반려 시 대안 사다리

1. 프롬프트에서 디테일 요구를 덜고 실루엣 대비를 올려 재생성
2. (스트립) 변화 요소를 **하나로** 줄여 재생성
3. (스트립) 스트립을 포기하고 **정지 1장 + 코드 기반 회전·스케일 변조**로 후퇴
4. 기존 에셋 유지

**반려는 실패가 아니라 기록 대상이다.** 반려본은 `ArtSource/Generated/Archive/`로 보내고
사유를 `ArtSource/Generated/Archive/REJECTED.md`에 남긴다.

## 10. 생성 → 반입 절차

```
① ChatGPT 이미지 생성 — 대상당 3안
     프롬프트 원문은 references/prompts.md
② 채택 1안 → ArtSource/Generated/Source/<Name>_Source.png
   반려 2안 → ArtSource/Generated/Archive/ + REJECTED.md 사유 기록
③ python tools/art_import.py
     크로마키→알파 + despill / 스트립 N등분 / 공통 바운딩박스 크롭 /
     정사각 패딩 / 리샘플 / 재결합
     변환 파라미터는 tools/art_import_log.md 에 append
④ Assets/Art/Sprites/Generated/<Name>.png 에 출력
     GeneratedSpritePostprocessor 가 임포트 설정을 자동 적용 (PPU·필터·슬라이싱)
⑤ 게임에서 육안 검증 (8. 채택 기준)
```

**수동 조정 금지.** PPU나 머티리얼 UV를 인스펙터에서 손으로 맞추기 시작하면 v1의 부채가 재발한다.
크기가 안 맞으면 규격이나 스크립트를 고친다.
