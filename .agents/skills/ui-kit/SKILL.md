# UI Kit — 코드기반 UGUI 제작 스킬

Rewind Survivors의 UI를 **외부 리소스 없이** 예쁘게 만드는 방법. 레퍼런스는
탕탕특공대 상점(그레이 백드롭 팝업 + 두꺼운 테두리 라운드 패널 + 3×N 그리드).

## 왜 코드기반인가
에이전트는 Unity 에디터를 드래그로 만질 수 없다. 그래서 UI를 **끝까지 텍스트로 저작
가능한 방식**으로 만든다. 다만 사용자는 에디터를 쓸 수 있으므로, 최종 산출물은
`[MenuItem]` 생성기가 만든 **편집 가능한 프리팹**이어야 한다 — 에이전트 저작 가능성과
사용자 수동 편집을 둘 다 챙긴다.

## 3-레이어 아키텍처

UI는 항상 이 순서로 만든다. 각 레이어는 아래 레이어에만 의존한다.

```
[3] 에디터 생성기  [MenuItem] → 계층 생성 + 앵커 + 참조 배선
        ↑ 사용
[2] 재사용 컴포넌트  UITheme(토큰) + 버튼/패널/카드/그리드 조립 헬퍼
        ↑ 사용
[1] 절차적 스프라이트  UISpriteFactory → 라운드/테두리/그림자 9-slice
```

### 레이어 1 — 절차적 스프라이트 (`UISpriteFactory`)
`Texture2D`에 픽셀을 직접 그려 라운드 사각형·테두리·그림자 스프라이트를 만든다.
`Sprite.Create`의 `border`로 9-slice를 지정해 크기가 바뀌어도 모서리가 안 깨진다.
한 번 만들어 static 캐시. **외부 PNG 0개.**
⚠️ **생성한 스프라이트를 프리팹/씬 `Image.sprite`에 직접 굽지 말 것** — 임시
`Texture2D`라 직렬화가 안 돼 런타임에 null(흰 박스)이 된다. `UIProceduralSprite`
컴포넌트로 **런타임에 재생성**해 적용한다.
→ 코드 전문 + 런타임 적용 규칙: `references/ugui-recipes.md`

### 레이어 2 — 재사용 컴포넌트 (`UITheme` + 헬퍼)
`UITheme`는 디자인 토큰(색·여백·라운드·폰트)을 담은 정적 상수 클래스.
버튼/패널/카드처럼 **여러 화면에서 반복되는** 조립만 헬퍼로 만든다.
한 화면에서만 쓰는 배치는 헬퍼로 빼지 않는다(AGENTS.md: 재사용될 때만 추상화).
→ 토큰 표: `references/design-tokens.md` · 헬퍼 코드: `references/ugui-recipes.md`

### 레이어 3 — 에디터 생성기 (`[MenuItem]`)
`Assets/Scripts/Editor/` 하위에 생성기를 둔다. 메뉴를 실행하면 씬/프리팹에 UI 계층을
만들고, 앵커·스프라이트·색을 세팅하고, **기존 스크립트의 `[SerializeField]` 참조를
코드로 자동 연결**한다(예: `UI_ShopPanel._cellContainer`, `_goldText`, `_closeButton`).
사용자는 메뉴 한 번 클릭 후 에디터에서 미세조정한다.
→ 생성기 패턴: `references/ugui-recipes.md`

## 워크플로우 (화면 하나를 만들 때)

1. **레퍼런스 해부** — 만들 화면의 구조를 요소 트리로 분해.
   예) 상점: 백드롭 → 팝업(헤더바 + 골드칩 + 그리드ScrollRect + 닫기버튼) → 셀(아이콘 + 라벨 + 가격버튼).
2. **기존 로직 확인** — 대상 스크립트를 Read. 어떤 `[SerializeField]`를 채워야 하는지,
   어떤 컨테이너에 셀이 Instantiate되는지 파악. **로직은 절대 수정하지 않는다.**
3. **레이어 1~2 구현/재사용** — 필요한 스프라이트·컴포넌트가 없으면 추가, 있으면 재사용.
4. **레이어 3 생성기 작성** — 계층·앵커·참조 배선. 기존 프리팹을 리스킨하는 경우
   기존 오브젝트를 찾아 컴포넌트만 갱신(파괴 후 재생성 대신 in-place 수정 우선).
5. **사용자 안내** — 에이전트는 결과를 못 본다. 반드시:
   > "에디터에서 `Tools/UI/{메뉴}` 실행 → 플레이 → 스크린샷 주세요"
   스크린샷을 받아 토큰/여백/정렬을 조정하며 반복.

## 디자인 원칙 (예쁨의 핵심)

"예쁨"은 스프라이트가 아니라 **일관성**에서 나온다. 항상 지킨다:

- **토큰만 쓴다** — 색/여백/라운드/폰트 크기는 `UITheme`에서만. 매직값 금지.
- **여백 스케일 고정** — 4·8·12·16·24·32·48만 사용. 임의 여백(7px, 13px) 금지.
- **정렬 그리드** — 요소는 8px 그리드에 스냅. 눈대중 배치 금지.
- **레이어드 표면** — 백드롭(어두움) < 팝업(밝음) < 카드(살짝 어두운 리세스)로 깊이 표현.
- **두꺼운 테두리 = 시그니처** — 탕탕 스타일. 라운드 사각형에 어두운 외곽선 5px.
- **위계 = 크기·굵기·색** — 타이틀은 크고 굵게, 보조 텍스트는 작고 흐리게(secondary).
- **CTA는 골드** — 구매/확인 버튼만 골드 액센트. 남발하면 위계가 죽는다.
- **여백이 답이다** — 요소가 답답하면 색을 더하지 말고 여백을 늘린다.

## 해상도 독립 (반드시)
- `CanvasScaler`: **Scale With Screen Size**, **Reference Resolution = 1080×1920 (모바일 세로)**,
  Match Width Or Height = 0.5. (이 프로젝트는 모바일 포트레이트 — AGENTS.md 기술 결정.)
- 모든 위젯은 **앵커·피벗을 명시**. 팝업은 화면 중앙 앵커, 헤더는 상단 스트레치,
  그리드는 부모 채우기 + `GridLayoutGroup` 또는 `ScrollRect`.
- 절대 좌표 고정 금지 — 다른 해상도에서 깨진다.

### 모바일 필수 — Safe Area (노치·상태바)
노치/상태바/홈 인디케이터에 걸리는 **상단·하단 바는 반드시 `SafeAreaFitter` 부착**.
이 컴포넌트가 `Screen.safeArea`를 정규화 앵커로 변환해 콘텐츠를 안전 영역 안으로 넣는다.
안 붙이면 재화바·타이틀이 노치에 파묻힌다. **Device Simulator의 노치 기기(iOS Notch
1170×2532 등)로 반드시 검증** — 일반 Game 뷰엔 노치가 없어 문제가 안 보인다.
실사용자 대다수는 ~19.5:9 긴 폰이므로 그 비율을 주 테스트로.

### TMP 한글 — 두부(□) 방지
`NotoSansKR SDF`라도 아틀라스에 **한글 글리프가 안 구워져 있으면 두부(□)로 렌더**된다.
한글이 필요하면 폰트 에셋의 **Atlas Population Mode = Dynamic**(런타임 온디맨드 생성)으로
바꾼다. 단 **이 프로젝트 UI는 영어로 통일**(로고·PLAY·SHOP·LEVEL UP 등) — 한글만 섞이면
짬뽕이라 덜 폴리시돼 보인다. 새 라벨은 영어로.
