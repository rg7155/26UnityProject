# 에디터 / 프로젝트 설정 메모

자주 까먹는 Unity 에디터·프로젝트 설정 기록.

## Run In Background — 포커스 잃어도 Play 계속
- 경로: `Edit → Project Settings → Player → Resolution and Presentation → Run In Background`
- 효과: 에디터 창이 포커스를 잃어도(다른 창 클릭) Play가 멈추지 않고 계속 실행
- 용도: 플레이 중 로그/다른 창 보며 디버깅할 때

## Post Processing 체크 — Bloom 등 후처리 표시
- 경로: `Main Camera → Camera 컴포넌트 → Post Processing` 체크
- 효과: 안 켜면 Bloom 등 Volume 후처리가 화면에 안 나옴
- 관련: Bloom은 `@PostFX` Global Volume의 Volume Profile에 Override로 들어있음

## Bloom Threshold — 스프라이트 글로우
- 경로: Volume Profile → Bloom → `Threshold`
- 값: 약 0.5 (낮출수록 더 많이 빛남)
- 이유: SpriteRenderer Color는 HDR가 아니라(밝기 1.0 한계) Threshold가 높으면 안 빛남. 낮춰서 밝은 LDR 색도 글로우

## Script Execution Order — EnemyJobScheduler 선행
- 경로: `Edit → Project Settings → Script Execution Order`
- 설정: `EnemyJobScheduler` = -100 (기본 0인 EnemyMover보다 먼저)
- 이유: Scheduler가 Separation 결과를 먼저 계산해야 EnemyMover가 그 프레임에 조회 가능

## LineRenderer / TrailRenderer Material
- 경로: 해당 컴포넌트 → Materials → Element 0
- 설정: `Sprites-Default` (또는 URP 2D Unlit)
- 이유: 미지정 시 분홍색으로 보임. 색은 컴포넌트/스크립트(_color)가 줌
- 대상: Bomb 원(ExplosionEffect), Lightning 볼트(LightningEffect), Orbiter Trail

## Order in Layer — 2D 스프라이트 렌더 순서
- 경로: SpriteRenderer → `Order in Layer` (Sorting Layer 는 `Default` 하나만 쓴다)
- 동작: 같은 Sorting Layer 안에서 **숫자가 클수록 위**. 음수 가능. 동점이면 z, z 도 같으면
  **내부 렌더러 순서(사실상 임의)** — 보장이 없으므로 겹치는 것끼리는 반드시 값을 명시한다

| 프리팹 / 오브젝트 | Order | 이유 |
|------|-------|------|
| `GameScene` > `BG_Base` (MeshRenderer) | **-100** | 배경은 모든 것의 아래. **0으로 두면 음수 Order인 보스 예고원을 통째로 가린다**(실제 발생) |
| `GameScene` > `BG_Detail` (MeshRenderer) | **-99** | 베이스 위, 그 외 모든 것 아래 |
| `Prefabs/Enemy/Boss_Monolith` > `Telegraph/Telegraph_Fill` | **-20** | 보스 예고는 바닥에 깔린 장판처럼 보여야 한다 |
| `Prefabs/Enemy/Boss_Monolith` > `Telegraph/Telegraph_Ring` | **-19** | 채움 위, 본체 아래 |
| `Prefabs/Enemy/Boss_Monolith` (루트) | **0** | 기준선 |
| `Prefabs/Weapon/Projectile`, `Projectile_Rapid`, `Orbiter`, `Bolt` | **5** | 플레이어 무기 |
| `Prefabs/Weapon/ExplosionEffect` (LineRenderer) | **6** | 폭발 원이 발사체 위 |
| `Prefabs/Enemy/Boss_RadialProjectile` | **8** | 보스 탄이 내 발사체보다 위 — 피해야 할 것이 우선 |
| `Prefabs/Player` | **10** | 플레이어는 무엇에도 가리면 안 된다 |
| `Prefabs/Effect/Death_Basic` | **20** | 사망 연출 |
| `Resources/UI/DamageText` (TMP 3D) | **30** | 숫자는 항상 최상단 |

- 10 단위로 띄운 건 나중에 사이에 끼워 넣기 위함
- SpriteRenderer 전용이 아니다. 위치만 다를 뿐 같은 값이 있다:
  - LineRenderer / TrailRenderer → 컴포넌트 하단
  - **TMP 3D(`TextMeshPro`, DamageText)** → `Extra Settings` 안 (MeshRenderer 로 그려진다)
- **Sorting Layer 는 추가하지 않는다** — 정렬 대상이 10개 내외라 Order 만으로 충분하고,
  레이어를 만들면 모든 렌더러에 지정해야 해서 누락 시 `Default`(목록 중간 고정)로 조용히 샌다.
  게다가 가장 수가 많은 잡몹은 인스턴싱이라 레이어로도 정렬되지 않는다.
  대상이 20개를 넘어가면 그때 `Background / Gameplay / VFX` 3단 묶음을 고려
- ⚠️ **Order 로 제어할 수 없는 것 2가지**
  - **잡몹** — SpriteRenderer 가 아니라 `Graphics.DrawMeshInstanced` 로 그려진다. 이 API 는
    Sorting Layer/Order 를 **무시하고** 머티리얼 render queue 로 정렬한다(잡몹은 작아서 실용상 무해)
  - **그리드 배경** — `RenderPipelineManager` 훅에서 직접 그린다
- ⚠️ Layer(오브젝트 이름 옆, Physics 용)와 **완전히 무관**하다. 이름만 비슷하다

### 검증
게임을 돌려 아래 4개를 눈으로 확인한다(전부 겹치는 조합이라 순서가 틀리면 바로 보인다).
1. 보스 장판 예고원이 **보스·플레이어 아래**로 깔린다
2. 방사탄 예고 링이 보스 본체 **밖으로** 나온다(반경 3.4 > 본체 반경 2)
3. 보스 탄이 플레이어 발사체·폭발보다 **위**에 그려진다
4. 데미지 숫자가 **무엇에도 가리지 않는다**

## 모바일 노치 확인 — Device Simulator
- 경로: `Game` 창 좌상단 드롭다운 → `Game`을 `Simulator`로 전환 → 기기 목록에서 노치 기종 선택
- Unity 6는 에디터 내장이라 별도 패키지 설치가 필요 없다(`manifest.json`에 안 보이는 이유).
- 검증 기종: **iOS Notch 1170×2532**. 규약 원문은 `.agents/skills/ui-kit/SKILL.md` "모바일 필수 — Safe Area".
- 용도: 상단 재화바·타이틀이 노치에 파묻히는지 확인. **일반 Game 뷰에는 노치가 없어 문제가 안 보인다.**

> ⚠️ **시뮬레이터 상태로 씬을 저장하지 말 것.** `SafeAreaFitter`가 `[ExecuteAlways]`라
> 에디터에서도 실행되어 **앵커를 씬에 구워 넣는다.** 시뮬레이터 해상도(1170×2532)로 계산된
> 앵커가 저장되면 일반 게임뷰(1080×1920)에서 UI가 깨진다.
> 확인이 끝나면 `Game` 뷰로 되돌린 뒤 저장한다.
> 전례: `.claude/knowledge/bug-patterns/editor-generator-scene-not-saved.md`

## Build Settings 씬 등록
- 경로: `File → Build Settings (Build Profiles) → Scene List`
- 등록: `Title`(index 0) / `GameScene` / `Result` 3개
- 이유: SceneManagerEx가 `type.ToString()`으로 로드 → 파일명이 enum(SceneType)과 정확히 일치해야 함. 미등록 씬은 로드 실패

## 생성 스프라이트 Import 규칙
- 경로: Project 창에서 PNG 선택 → Inspector
- `Texture Type`: `Sprite (2D and UI)`
- `Sprite Mode`: `Single`
- `Pivot`: `Center`
- `Filter Mode`: `Bilinear`
- `Compression`: `None`
- `Generate Mip Maps`: 끔
- `Wrap Mode`: `Clamp`
- `Alpha Source`: `Input Texture Alpha`

### 크기 조절 원칙
- 생성 이미지의 해상도와 여백 차이는 `Pixels Per Unit (PPU)`으로 보정한다.
- PPU가 클수록 스프라이트는 작아진다.
- 단순 이미지 크기 보정에는 프리팹 `Transform Scale`을 사용하지 않는다. Transform Scale은 게임플레이 크기와 Collider에도 영향을 준다.
- 이미지 교체 후에는 SpriteRenderer의 시각 크기와 Collider 크기를 함께 확인한다.

### 현재 생성 에셋 PPU 시작값
| 에셋 | PPU | 비고 |
|------|----:|------|
| `PlayerEnergyCoreSymmetric` | 577 | 플레이어 Collider 기준 |
| `BossMonolithSymmetric` | 1150 | Boss_Monolith Transform Scale 4 기준 |
| `OrbiterEnergyBlade` | 800 | Orbiter Transform Scale 0.8 기준 |

> ⚠️ 위 PPU 표는 **art-gen 파이프라인 도입(2026-09) 이전의 수동값**이다. 현재는
> `Assets/Scripts/Editor/GeneratedSpritePostprocessor.cs`가 임포트 시 자동으로 지정하므로,
> 값이 안 맞으면 인스펙터가 아니라 그 스크립트를 고친다.
> 규격 정본은 `.agents/skills/art-gen/references/art-spec.md`.

### GPU 인스턴싱 적 이미지
- `EnemyInstanceRenderer`로 그리는 적은 SpriteRenderer를 거치지 않아 PPU가 적용되지 않는다.
- 이미지 여백 보정은 각 전용 Material의 `Base Map Scale / Offset`으로 처리한다.
- 대상 Material: `Mat_Enemy_Basic_Sprite`, `Mat_Enemy_Speeder_Sprite`, `Mat_Enemy_Tanker_Sprite`
