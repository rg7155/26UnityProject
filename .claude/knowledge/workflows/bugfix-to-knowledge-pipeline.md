## 목적
같은 패턴의 버그가 재발할 때 즉시 해결책을 재사용하기 위해,
수정 경험을 검색 가능한 KB 엔트리로 축적한다.

## 절차

### 1. 착수 전 — KB 검색
버그/기능 요청을 받으면 구현 전에 `.claude/knowledge/`를 먼저 검색한다.
```
grep -ri "핵심증상키워드" .claude/knowledge/
```
`symptom`·`tags` 프론트매터로 유사 패턴을 찾고, 있으면 그 해결책을 참조.

### 2. 구현 — unity-dev 파이프라인
Planner → Coder → Reviewer 를 거쳐 수정.

### 3. 수정 후 — 엔트리화 판단
아래를 **모두** 만족할 때만 새 엔트리를 만든다 (억지로 채우지 않음):
- [ ] 재발 위험이 실제로 있는 패턴인가? (일회성 오타·설정 실수는 제외)
- [ ] "재인식 패턴"을 한 줄로 요약할 수 있는가?
- [ ] 기존 엔트리와 중복되지 않는가?

### 4. 작성
- 위치: `bug-patterns/` (버그) · `lessons-learned/` (설계 교훈) · `workflows/` (절차)
- 프론트매터: `tags`, `symptom`, `commit` 필수
- 본문: `증상 → 근본 원인 → 해결 → 재인식 패턴 ⚠️`
- `README.md` 인덱스에 한 줄 추가

## 역할 경계 (다른 문서와 혼동 금지)
- **아키텍처.md** = 시스템이 *무엇인가* (정적 구조)
- **개발_진행상황.md** = *완료/예정* (시간축)
- **KB** = 문제를 *어떻게 풀었나 + 또 만나면* (검색·재사용)
